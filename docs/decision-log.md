## Phase 2 decisions (2026-10-27)

| Id | Decision | Rationale | Alternatives considered | Revisit if |
|---|---|---|---|---|
| D-048 | **Own safe expression parser and evaluator** (`src/checking/expr/`) and **own unit system** (`src/checking/units.ts`), replacing the planned Compute Engine and mathjs (D-008). The parser builds a small AST with hard limits (500 characters, 300 tokens, depth 40, 400 nodes, 30-digit numbers); evaluation compiles the AST to closures. No `eval`, `Function` or `new Function` anywhere. | Full control of every documented trap and of `indeterminate`; no code-execution surface (mathjs `evaluate` is a mini-language); deterministic; the whole worker is about 15 KB gzip instead of the 450 KB budget. | Compute Engine (heavy, MathJSON canonicalisation we'd still have to constrain), mathjs (larger surface). | We need symbolic manipulation (simplification, solving) rather than equivalence checking. |
| D-049 | Maths input is a **text field with a symbol keypad and a live KaTeX preview** ("Reads as …"), not MathLive. Accepts `√`, `π`, superscripts, `|x|`, `sin^2 x`, implicit multiplication. | Works with every screen reader and phone keyboard as plain text; no web-component or font payload; the preview catches misreads before checking. | MathLive (`<math-field>`). | Students struggle to type fractions on phones (watch Phase 3 feedback). |
| D-050 | Check **time budget 300 ms** per check (docs/05 said 150 ms). The timer starts only after the worker's ready handshake. On timeout the worker is terminated and restarted and the result is `indeterminate` (never incorrect, no attempt used). Without Worker support, checks run inline. | 150 ms gave false timeouts on throttled phones for long expressions; 300 ms is still imperceptible after pressing *Check*. | 150 ms; no restart. | Real-device timing shows timeouts on ordinary answers. |
| D-051 | `log` means **natural log** by default (NCERT convention in Class 11–12 calculus); a template can set `logBase: "10"`. `ln` is always natural. | Matches the textbooks the students use. | Base 10 default. | Content needs base 10 broadly. |
| D-052 | Expression equivalence: **24 seeded sample points**, at least 10 valid; equivalent if every difference ≤ 1e-8 (relative), different if any > 1e-5, otherwise `indeterminate`. Reference values beyond 1e8 are skipped. If the student's expression is undefined where the reference is defined, it is different. `specialPoints` and `domainMustMatch` handle removable discontinuities. | Covers √(x²) vs x, log(x²) vs 2 log x, (x²−1)/(x−1) vs x+1 and tan x near π/2 without symbolic algebra. | Symbolic tie-break (needs a CAS). | A trap appears that sampling can't separate. |
| D-053 | **Proposed amendment to D-025 (needs your approval).** The student manifest includes templates that pass validation and are `in-review` or `approved`; `draft`, `auto-checked` and `retired` never ship. An attempt counts toward mastery **only** if its template is `approved` *and* its content hash still matches the approval; every attempt records `countsTowardMastery`, and skill independence ignores attempts where it isn't `true`. An approved template edited after review fails validation (and the build) until it is re-reviewed. | Keeps the in-review questions you approved in Phase 1 (D-043) playable while guaranteeing they never count. D-025 as written would remove every question from the app until a human approves them. | D-025 unchanged (ship nothing until approved). | You prefer to ship approved content only. |
| D-054 | **Review tool** (`npm run content:review`): a local server on 127.0.0.1 that shows every review variation in full and links each to the live player. A decision needs a named reviewer, a tick for every variation, an attestation, and a session code printed only in the terminal. It records `reviewedBy`, `reviewedAt`, `contentHash` and a review-log entry. There is no command-line or scripted approval path. Requesting changes withdraws an approval. | Human review stays mandatory and auditable in git. | A CLI `approve` command (too easy to automate). | A second reviewer or sign-off is wanted. |
| D-055 | **Hints and feedback never give the answer away.** The validator fails a template whose first two hints contain the answer. Widgets gained answer-safe display options (graph areas without values, symbolic components "Weight sin θ", meters without numbers, hidden agents, motion numbers hidden until the solution reveals them). Consequences play out the student's own answer (the braking distance they gave, the launch speed their range implies, their f′ as a tangent, the race their ordering assumes), never the correct state, until the question ends; then the correct state is shown beside theirs. | docs/07 "only the consequence is shown, never the correct state". | Show the real outcome as the consequence. | — |
| D-056 | The migrated Phase 1 diagnostics use the four core widgets where they fit (v–t area → graph plot, braking → motion track, interval → number line, dot product → vector board). The circuit, Venn and box-diagonal visuals are kept as a non-interactive `figure` widget with the same cue system; the interactive `circuit-board` and `venn` widgets stay in Phase 6. | Preserves the reviewed visuals without building Phase 6 widgets early. | Rebuild them now. | — |
